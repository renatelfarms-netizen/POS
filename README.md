# Tessa POS (test version)

Built from the Renatel Shop app. Many shops each run their own shop on one website.

- `/` platform page: main page; `/register` create a shop (free to use); `/login` find your shop
- `/<shop-link>` a shop's app, e.g. `/kofi-mart`. Staff log in there with name + password.
- `/admin` platform admin: every shop, pause / open, notes
- `/help` help page: step-by-step guides with pictures and the support WhatsApp number (`help.html`)

Each shop's data, staff, logins, backups and limits are kept apart by shop id.
A login token from one shop is refused by every other shop.

## Each shop also gets (same features as Renatel Shop)
- **Online shop** at `/<shop-link>/shop`: customers create an account, buy and pay; stock is taken from the shop's branch. Receipts at `/<shop-link>/r/…`, credit invoices at `/<shop-link>/i/…`, product photos at `/<shop-link>/img/…`.
- **Paystack** (Mobile Money and cards): each shop owner pastes their own secret key in Online shop → Settings. Webhook: `/<shop-link>/api/store/paystack`.
- **SMS (USMS-GH)**: each shop uses its own USMS-GH token and sender ID. Receipt SMS, password reset codes, credit reminders and delivery texts.
- **Credit reminders** (daily, once per customer per day; the platform runs the job for every open shop) and "I have paid" approval.
- **Delivery SMS**: rider jobs, on the way, courier handover, delivered, instructions.
- **Reminder SMS to shop owners** (platform, from the shared SMS account): owners who created a shop but added nothing (day 1, 3, 7), set it up but never used it (2, 5, 10 days after they were last seen) or went quiet after using it (7, 14, 30 days) get a short text with their shop link and the support WhatsApp number (`SUPPORT_WHATSAPP`, default 0244022727). Shops in use get nothing. Sent 9am to 6pm Ghana time, each message once (`mt_job_once`). Off until switched on at `/admin`, which shows who is due, the exact text, what was sent, and lets one shop be muted. Settings and the sent list are kept in `mt_kv` 'nudge'.
- **Staff password hashes never reach the browser.** The server strips each staff member's `pin` from the `shop/main` doc on the `/api/db` pull (the page uses `hasPw` instead) and re-attaches the stored hash on write, refusing the write if it can't read the current doc first (so a save can never blank passwords). On the website, staff login, change-password and manager-approved resets go through the server (`/api/login`, `/api/verify`, `/api/reset/approve`); the offline standalone build still checks locally. The shop recovery code (`set.rc`) and the short-lived emailed reset code (`rst`) are still sent and are a planned follow-up.
- **Roles are enforced on the server.** When anyone but an owner saves the shop document (`shop/main`), the server rebuilds it from the stored copy and keeps only what their role allows: their own profile and password, account lock-outs from wrong tries, and day-to-day lists (expense types, product categories, suppliers). Staff roles, permissions and screens, other people's passwords, unlocking, adding or removing staff, and the owner-only settings in `OWNER_SET` (recovery code, sign-out-all, password rules, idle logout, stock-value privacy, discount limit, tax, payment methods, branches, currency, buyer rule, auto SMS, shop name) stay as stored. Only an owner can delete the shop document. On the website, the staff screen's email-code and recovery-code resets use the server (`/api/reset/code`, `/api/reset/email`, `/api/reset`).
- **Product photos** are kept on the hosting in `PHOTO_DIR` (default `~/tessa-photos/<shop id>/`, outside the website folder so deploys don't touch it), not in Supabase. Photos from before 22 Nov 2026 were copied there once from Supabase (`mt_photos`; the 21 Nov originals went to `_originals-20261121/`); `/api/platform/photos-status` shows the counts. Include this folder in the hosting's backups.
- **Admin page** (`/admin`): boxes on top count the shops (all, joined today, joined this week, in use, set up but not used, not started, gone quiet, paused); tap one to see those shops. The list shows for each shop its type, town, products, staff, sales, online orders and when it was last active, with search, filters, type of business and ordering (newest first by default). Payments, SMS and reminder settings are on their own tab. The details come from one database call, `mt_shop_stats`; without it the list still loads, with fewer details.
- **Withdrawals**: shops that take online payments through the platform's Paystack see their money in Online shop → Settings → Payments (and on top of the Online shop page). The **owner only** presses Withdraw (any amount up to what is still owed, no minimum, one request at a time). The request shows at the top of `/admin` (🔔 Withdrawal requests, with the amount and the account to pay); the admin pays within 24 hours and records the payout, which closes the request and texts the owner. Requests are kept per shop in `mt_docs` ('platWd'); `mt_wd_list` reads them all for `/admin`.
- **Day-to-day data follows staff permissions on the server.** For non-owners, `/api/db/put` and `/api/db/del` on `sales`, `expenses`, `products`, `customers` (and `accra_` copies) apply `limitData()` using the stored staff record (`powers()` mirrors the app's ROLES/GRANT/perms): new sales, expenses and customers always save; old sale amounts need edit (owner/manager/`perms.edit`), refunds need owner/manager (delivery staff may add a no-money 'Not collected' void), removing or changing old records and deleting need `perms.del`, product details and new products need the Inventory/Purchases/Warehouse screens (online-shop staff may set `hideOnline`/`img`), stock only goes up for stock/refund/edit/delete/inventory/delivery staff, and only Customers-screen staff (or refund/edit/delete) can lower a balance. The server reads the stored doc first and refuses the save if it can't.
- **Attempt limits don't trust the IP alone.** `X-Forwarded-For` can be faked, so password checks (`/api/verify`, per staff), approval resets (per approver), recovery-code resets (per shop), admin login (site-wide 20/15 min), reset-code sending (6/hour per person, also per phone in the online shop), new shops (40/hour site-wide), emails (150/day per shop) and photo uploads (300/hour per staff) also have limits keyed on the account. The activity trail and stock movements (`log`, `moves`, `whMoves`) are append-only for non-owners for 7 days, and the server's own `_server` log pages can't be changed by them; a refused delete answers 200 so the app doesn't retry forever.
- **Staff only download what their screens use.** On the `/api/db` pull, non-owners get `sales`/`customers` only with a selling, receipts, customers, delivery, courier or reports screen, `expenses` only with expenses, reports or purchases, and the activity trail (`log`) only as managers (`canSee()`); `set.rc` is sent to them as `'hidden'`, and a save carrying `'hidden'` keeps the stored code. After an in-app sign-in on the website the app re-downloads from the start (`cloud.resync()`), so an owner signing in on a cashier's till gets everything. `deliveries` (change needs delivery/courier screens or edit), `pos`, `transfers`, `trReq`, `whPos`, `whItems` (need Inventory/Purchases/Warehouse) follow the same `limitData()` rules; delivery staff may turn a sale's 'On delivery' payment into the method actually used for the same amount (`codSwap()`).
- **Stored data can't carry script.** Number fields (`qty`, `price`, `stock`, `total`, `amt`, … see `NUM_KEYS`) are turned into numbers and `status` labels lose markup characters on every save and every download (`cleanDoc()`), and the currency symbol is cleaned on save, load and download (`curFix()`), because many screens and the admin view print them unescaped. The download only ever contains the app's own collections (`DB_COLS`): online orders, the payout account, withdrawals and payment claims stay on the server. Recorded school fee payments (`students[].pays`) and rider hand-ins (`remits`) can't be changed or removed by staff without delete permission. Test: `xss_ui.js` plants labelled script in every field and opens every owner, cashier, public and admin screen.
- **Accounts and SMS.** An online-shop account only shows the customer's credit balance after the phone is confirmed by a texted code (`/api/store/verify/code`, `/api/store/verify`, sets `ver`; a password reset by SMS also confirms it). Staff SMS routes are limited per person, not per IP: receipts 120/hour, credit reminders 40/hour, delivery messages 100/hour, bulk 10 batches/hour and 1,500 messages/day, and bulk SMS needs the school, courier, delivery or customers screen. Reset codes are also capped per day (staff 12, online customers 12, login-page email 10). A new or reset password signs out that person's other devices (`pwAt`/`pwDev` on the staff record, checked in `caller()`); the device that changed it stays in.
- **Restaurant bills, courier jobs, quotes, flagged sales.** For non-owners: an unpaid bill (`rtabs`) can only be voided by a manager or someone with delete permission, and a paid bill doesn't change without edit permission; courier `jobs` need delete permission to remove; a quote can be deleted with edit/delete permission or by whoever made it (refused deletes answer 200 and keep the doc). New sales from anyone but owners/managers that are below the product's price or over `set.maxDisc` are kept but get `flag`, and a '⚠ Check this sale' line goes in the activity trail (shown on the owner's security card).
- **Online shop without payments, links, exports, request size.** With no Paystack key (test mode) an online order is recorded as 'On delivery' and its delivery has `cod` = the total, so the money is collected on pickup/delivery (the test pay button no longer makes it look paid). Links in SMS, emails and payment pages always use the real domain (`hostOf()` ignores other Host / X-Forwarded-Host values). CSV exports put a `'` before text starting with = + - @ (not plain numbers). Request bodies are limited to 256 KB except logged-in sync and email (25 MB), photos (3 MB) and bulk SMS (2 MB); `emailOK()` rejects anything over 254 characters before its pattern. Saving the payout account emails the owner(s), and /admin marks a withdrawal whose account changed less than 48 hours before it.
- **Shop settings are an allow-list for staff.** When a non-owner saves `shop/main`, the settings start from the stored copy and only `cats`, `pcats`, `autoPrint`, `paper`, `dlvRider`, the counters `rst.no` and `cour.seq` (whole `rst`/`cour` only if not set up yet) and, with the school screen, `sch` are taken from them. Everything else — shop phone and address, invoice payment details (`credPayInfo`), receipt design (`rx`), online shop (`store`), SMS texts, delivery prices — is the owner's. The receipt logo (`set.rx.logo`) must be a `data:image/…;base64` picture for everyone (`LOGO_RX` in `curFix()`).
- **Who may create what (night review).** New sales only from the selling or courier screens, new expenses only from the expenses or purchases screens (`NEW_REC`); customers only change for staff with selling, receipts, customers, delivery or courier screens, products for those plus inventory/purchases/warehouse (`TOUCH`). School: fee amounts, admission fees and student bills need the 'Create bills' permission and new fee payments need 'Fees and payments' (`spHas()`, same defaults as the app's `SPDEF`). New free shops (under 7 days, unpaid) can send 20 emails a day, and the platform at most 1,000 an hour; online sign-ups are capped at 300 a day per shop and orders at 30 a day per account. Pages carry `Content-Security-Policy: base-uri 'self'; object-src 'none'; frame-ancestors 'self'; form-action 'self' https://checkout.paystack.com` and a `Permissions-Policy`.
- Customer logins, signed links, photos, keys, one-time codes and jobs are kept apart by shop (`schema_shop_features.sql`).

## Files
- `server.js` web server (no dependencies)
- `index.html` the shop app
- `landing.html` platform page, `admin.html` admin page
- `schema.sql` the database tables and functions (run once in Supabase)
- `schema_shop_features.sql` per-shop tables and functions for the online shop, SMS and reminders (run once, after schema.sql)
- `store.js`, `store.html` the online shop (shared with Renatel Shop)

## Environment variables
- `SUPABASE_URL`, `SUPABASE_KEY`, `SUPABASE_BACKUP_TOKEN` (`SUPABASE_KEY` is the secret / service_role key; the database functions refuse the public key)
- `PLATFORM_ADMIN_PASSWORD` password for /admin
- `PLATFORM_NAME` (default "Tessa POS"), `PLATFORM_HOST` (e.g. the domain)
- `MAIL_API_BASE` optional; mail settings are read from `site_secret_get` in Supabase
